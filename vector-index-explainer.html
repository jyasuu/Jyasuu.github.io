向量索引 · 近似最近鄰搜尋

資料變多之後，「找最近的向量」該怎麼辦

當向量表只有幾千筆，逐一算距離、排序取前 k 個完全沒問題。可是資料量一旦到幾百萬筆， 這種暴力比對就會變成瓶頸。HNSW 與 IVFFlat 是兩種常見的解法，用「放棄一點精確度」 換回「大幅減少要比對的向量數」。下面用可互動的圖表和偽代碼拆解它們各自的直覺。

HNSW · Hierarchical Navigable Small World

先跳遠一點，再慢慢逼近

HNSW 把所有向量放進一個多層的圖。最上層節點最少、邊最長，適合先大步跳到查詢點附近的區域； 越往下層節點越密、邊越短，適合做精細調整。搜尋時從最上層的固定入口點開始， 每層都用「貪婪搜尋」——不斷走向目前鄰居中離查詢點更近的那個，直到找不到更近的為止， 再把落腳點帶到下一層繼續走，一路走到最底層（第 0 層，包含全部節點）為止。

這個機制像機場轉機：越上層越像洲際航班的樞紐機場，先跨過大片距離； 越下層越像市內公車站，負責最後一段的精確定位。

參數怎麼影響它

M — 每個節點在圖中保留的鄰居數上限。M 越大，圖越密、召回率越高，但記憶體與建構時間也越高。
efConstruction — 建圖時，每次插入節點要探索的候選集合大小。越大，圖建得越精細，插入越慢。
efSearch — 查詢時最底層搜尋維持的候選集合大小。越大越精確、越慢；這是查詢時唯一需要即時調整的旋鈕。

偽代碼

// 插入一個新向量 q
function HNSW_INSERT(hnsw, q):
    L = random_level()                  // 依機率分布抽出 q 最高會出現在哪一層
    ep = hnsw.entry_point
    for lc = hnsw.max_level downto L+1:
        ep = SEARCH_LAYER(q, ep, ef=1, lc).nearest    // 只需知道大概方向
    for lc = min(L, hnsw.max_level) downto 0:
        candidates = SEARCH_LAYER(q, ep, ef=efConstruction, lc)
        neighbors  = SELECT_NEIGHBORS(candidates, M)
        connect q <-> neighbors on layer lc
        for each neighbor: prune its edge list to size <= Mmax
        ep = nearest(candidates)
    if L > hnsw.max_level:
        hnsw.entry_point = q
        hnsw.max_level = L

// 查詢最近的 k 個向量
function HNSW_SEARCH(hnsw, q, k, ef):
    ep = hnsw.entry_point
    for lc = hnsw.max_level downto 1:
        ep = SEARCH_LAYER(q, ep, ef=1, lc).nearest    // 逐層貪婪下降
    candidates = SEARCH_LAYER(q, ep, ef=max(ef, k), 0) // 底層做較寬的搜尋
    return top_k(candidates, k)

function SEARCH_LAYER(q, entry, ef, lc):
    visited    = { entry }
    candidates = { entry }        // 待探索，依距離排序的優先隊列
    result     = { entry }        // 目前找到的最佳集合，容量上限 ef
    while candidates not empty:
        c = candidates.pop_closest_to(q)
        if dist(c, q) > result.farthest_dist and |result| >= ef:
            break
        for neighbor in graph[lc].neighbors(c):
            if neighbor not in visited:
                visited.add(neighbor)
                if dist(neighbor, q) < result.farthest_dist or |result| < ef:
                    candidates.add(neighbor)
                    result.add(neighbor)
                    if |result| > ef: result.remove_farthest()
    return result
IVFFlat · Inverted File with Flat vectors

先分區，再只搜幾個區

IVFFlat 的想法簡單很多：先用 k-means 把所有向量分成 k 群，每群有一個中心點（centroid）， 並把每個向量登記在自己所屬的那份「倒排列表」裡。查詢時不需要比對全部資料， 只要先找出離查詢點最近的幾個中心點（數量由 nprobe 決定）， 再只在這幾份列表裡逐一比對距離。nprobe 越大，涵蓋的區域越廣、越接近暴力搜尋的準確度， 但也要多比對更多向量。

這比較像用郵遞區號先篩選要跑哪幾個郵局轄區送信，而不是把全國每一戶都問一遍。

參數怎麼影響它

lists — 分群數量 k。群越多，每群越小、搜尋越快，但需要更大的 nprobe 才能維持召回率。常見經驗值是資料量的平方根量級。
nprobe — 查詢時要探索的群數。等於 lists 時等同暴力搜尋；等於 1 時最快但容易漏掉剛好落在邊界另一側的最近向量。

偽代碼

// 建立索引
function IVFFLAT_BUILD(vectors, k, iters):
    centroids = kmeans_init(vectors, k)         // 例如 k-means++ 初始化
    for i in 1..iters:
        for v in vectors:
            assign[v] = argmin_c dist(v, centroids[c])
        for c in 1..k:
            centroids[c] = mean({ v | assign[v] == c })

    lists = k 份空的倒排列表
    for v in vectors:
        lists[assign[v]].append(v)
    return centroids, lists

// 查詢最近的 k 個向量
function IVFFLAT_SEARCH(query, centroids, lists, nprobe, k):
    ranked = sort(centroids by dist(query, centroid))
    probe_set = ranked[0 : nprobe]              // 只挑最近的 nprobe 個群

    candidates = []
    for c in probe_set:
        candidates.extend(lists[c])             // 只掃描這幾份列表，不碰其他群

    scored = [ (v, dist(query, v)) for v in candidates ]
    return top_k(scored, k)

兩者怎麼選

兩者都是「用結構換速度」，但換的方式不同：HNSW 換的是圖遍歷的跳躍能力， IVFFlat 換的是把向量空間先切好區塊。沒有哪個絕對更好，取決於資料規模、 更新頻率，以及你能接受多少召回率的犧牲。

HNSWIVFFlat
建構時間較慢，需逐點插入並維護多層圖較快，只需跑幾輪 k-means
查詢速度很快，層與層之間可跨越大量節點取決於分群數與 nprobe，通常也很快
記憶體用量較高，每個節點要存多層鄰居列表較低，只需存 centroid 與原始向量
召回率調整調整 efSearch，越大越準越慢調整 nprobe，越大越準越慢
動態新增資料支援線上插入，但刪除、大量更新較麻煩新增資料容易，但資料分布改變後 centroid 會失準，需重新訓練
適合情境召回率要求高、資料量大且相對穩定的線上服務資料量極大、可接受稍低召回、偏好簡單可重建的批次流程

在 pgvector 裡兩者都是原生索引類型：USING hnsw (m, ef_construction) 建立索引後， 查詢時用 SET hnsw.ef_search = ... 調整；USING ivfflat (lists) 建立索引後， 查詢時用 SET ivfflat.probes = ... 調整——對應的就是上面偽代碼裡的同一組參數。
